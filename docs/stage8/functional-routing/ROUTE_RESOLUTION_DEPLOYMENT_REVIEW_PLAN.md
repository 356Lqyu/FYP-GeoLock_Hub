## Failure, pause and reconciliation

- Before COMMIT, SQL errors roll back the entire migration. If connection outcome
  is uncertain, inspect schema/function fingerprints and gate state first; never
  blindly re-execute the file or infer rollback from a missing client reply.
- After COMMIT, stop new resolution writes through the private gate only with
  separately approved operator action. Preserve case records, request IDs, evidence
  and route holds. Owner-scoped receipts remain readable for reconciliation.
- No destructive DOWN migration is supplied. A reviewed forward correction must
  preserve ABANDONED history and guards if any such routes exist. Do not drop cases,
  delete receipts, restore old status constraints over new data, or revive released
  claims. New claims after legitimate release have independent identities/deadlines.
- A finalization failure rolls back all of that attempt. Earlier committed genuine
  collection survives; it must never be undone to simplify recovery. Lost replies
  are reconciled with the same principal/request receipt, without new IDs or retries.
- Unsafe expired listings remain MANUAL_REVIEW. There is no approved withdrawal,
  forced release, custody override or automatic timeout resolution in this prototype.
