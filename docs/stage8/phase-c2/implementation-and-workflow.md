## Remaining database changes before a live demonstration

These are precise logical changes requiring concrete SQL review/approval; no migration was created or executed in this checkpoint.

1. **C0/C2 security and graph/matrix authority:** private routing schema with explicit owner/RLS/table/function grants, safe search paths and distinct trusted planner/validator roles. Add graph revision manifests binding approved coverage, complete active-node/edge content digests, same-path time profile and explicit precision policy. Add immutable matrix manifests/cells or bounded canonical JSON, ordered nodes, paired costs, AVAILABLE/UNREACHABLE/MISSING classification, graph FK, payload hash, build version and sealing guards. Start with one frozen graph rather than silently adding an edge version column while global node keys remain unversioned. A new protected sealing/publication RPC is required; no change to donation lifecycle.
2. **C3 planning snapshots/configuration:** planning run identity/owner/cutoff; exact task/claim/lease/listing/source and fleet projections, exclusions, vehicle versions, location generation, explicit time windows/service/mandatory policy, solver/objective configuration, matrix FK and canonical payload digest. Capture source inputs consistently before asynchronous matrix/solve work and seal afterward with freshness checks; do not hold lifecycle locks during solving. Append-only sealed children and protected NGO-scoped read/create/seal operations are required. Source tokens can hash joined authoritative fields; adding a version column to every existing lifecycle table is not automatically required.
3. **C4 plan and independent validation bindings:** extend existing routes with snapshot FK, plan hash/version and trusted validation record FK; freeze accepted stops/order/timing/load/depot data. Add composite stop task/NGO ownership FK, immutable accepted-content guards and idempotent publication/acceptance records. Add validator-only attestation/acceptance RPC and protect DRAFT → VALIDATED. Harden existing `assign_task_to_route` and restrict alternative route/stop/assignment writers simultaneously, so unvalidated comparison candidates cannot change CONFIRMED tasks to PLANNED.
4. **C5 authorization/bookings:** immutable route authorization plus per-task/claim consumption/revocation metadata, snapshot/matrix/plan/validator bindings, deadlines and expected source/vehicle versions. Add exclusive or serialized vehicle-time bookings, protected issue/revoke/activate functions, replay and audit. Protect VALIDATED → AUTHORISED. No client success boolean or client NGO ID supplies authority.
5. **C6 existing dispatch gate:** separately reviewed change to the existing `start_pickup(uuid)` transaction and alternate task writers; recheck exact permit, source freshness, vehicle/depot/booking and execution time, atomically consume one item with existing task/donation transition, activate route once and retain later-stop permits. Define compatibility for already-started pickup and legitimate single-stop workflows; no implicit bypass or default vehicle. Flutter changes alone are insufficient.
6. **Protected completion/release:** new close-owned-route RPC with expected route/version/digest and request key. Require successful existing collection for every route stop, matching completed claim/lease authority and no unresolved activity; clear only this route's assignments before COMPLETED, release its booking/authorization lifecycle appropriately and recompute all vehicle holds in one transaction. Retain historical stops and audit. No automatic vehicle availability toggle. A separate unstarted-cancel/deplan operation may use existing task PLANNED → CONFIRMED / route CANCELLED or STALE only after reviewed authority checks.

**Production blocker beyond a happy-path demo:** recovery currently treats any historical route-stop reference as uncertainty. Safe abandonment must distinguish active bindings from retained history through a separately reviewed membership/recovery policy, not deletion of real stops. Partial pickup, cancellation, expired permits/leases, multiple holds and emergency depot changes need explicit operational tests. No recovery or hub function was changed here.
