## Stage B direct-pickup test specification

Use a NEW disposable local cluster on loopback only, no external DSN. Current functions and triggers must be installed from current source. Fixture Auth/Storage/road doubles must be explicitly declared; they do not demonstrate true JWT/RLS/Storage or operational graph coverage. A future fixture adapter may build synthetic rows in this disposable schema but must not be reused as a live setup tool.

1. Create a single eligible synthetic NGO, donor, vehicle and direct donation using the tested protected interfaces where available; claim through actual current claim_listing. Assert one 360-minute lease and one CONFIRMED task, correct CLAIMED donation/listing, current audit/failure contract.
2. Snapshot and evaluate the selected vehicle/task with explicit graph/policy. Verify all four advisory results, separate validator attestation and exact payload/digest binding. No authority/booking before publication.
3. Authorize under the NGO identity. Verify one route, stop, binding/item and task/vehicle reservation, task PLANNED; same request replay changes nothing.
4. Read owned route. At valid authorized departure, start through public start_pickup. Verify transaction-bound consumed permit, route IN_PROGRESS, task DISPATCHED and donation PICKUP_IN_PROGRESS; actual claim/lease audit linkage.
5. Complete with handover true and current active lease. Verify task/donation COLLECTED, listing CLOSED, claim/lease COMPLETED; bookings still held. False handover/expired lease/foreign actor/skip-start must roll back.
6. Confirm depot return and close owned route. Verify only its assignment/booking released and route COMPLETED. Repeated closure is safe; early/foreign closure fails.
7. Repeat with injected required-write failures, commit-before-response-loss adapters and duplicate/concurrent commands. Preserve uncertainty; state-based reads resolve void pickup calls rather than changing signatures for convenience.
8. Run bridge cases before deployment discussion: managed positive two-party handover; disputed/negative evidence; resolved same-key replay; legacy in-flight path; permit cannot be reused; missing binding fails closed. Recovery and safe-release bodies remain current and unchanged.
9. Compare all outside-fixture business/audit records and preserved source/guards. A failure aborts acceptance; do not weaken assertions or rewrite expected outputs from observed failures.

The existing production snapshot selects owned eligible tasks, not a user-specified one-task filter. The future direct DEV pilot must use an approved isolated identity whose eligible task set is exactly one; do not borrow operational accounts. The manifest template has approved=false and is not executable authority.
